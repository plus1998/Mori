# 排队消息场景排查

验证日期：2026-10-12。桌面 dev 主进程修改后重新编译并重启，通过 CDP 9333 操作专用测试会话。

## 数据和调度约束

- V2 用户消息保存接收事实、正文和附件，`queued` 表示尚未投递。队列记录保存顺序、优先级和投递过程；当前正文仍有副本。
- 编辑正文、替换/删除图片必须同时更新队列和 V2，并在同一 SQLite 事务提交；失败时两边都回滚。
- 取消未发送消息必须同时取消队列项和删除 V2 接收记录；启动恢复不得发送已取消或被替代的消息。
- 已有队列记录的 V2 接收消息只能通过队列调度。重启恢复不得直接发送并绕过排序、暂停或编辑锁。
- 正常完成自动领取下一条；手动停止、运行错误、异常退出保护剩余队列并暂停。用户点击继续后，旧停止清理不能覆盖这个新操作。
- 编辑期间保持队列等待；保存、取消编辑、切换会话和新建对话必须释放原会话的编辑锁。
- 手动引导可以越过用户暂停发送指定一条，其他条目保持暂停；引导不能越过编辑和阻塞审批/提问。
- 尚在准备阶段的排队续跑可被暂停/停止撤销；撤销后归还队列，不能提前把 V2 标记为已发送。
- 清空最后一条释放空队列的暂停；失败的投递不能残留为可重启自动发送的 V2 消息。

## 发现并修复的问题

1. 排队编辑只更新队列表，V2 正文仍旧。现在编辑正文和附件同事务更新，桌面和移动端都支持附件替换 effect。
2. 排队编辑的图片没有经过持久对象存储。现在先保存为内容引用，再提交编辑；删图同步发送空附件列表。
3. 停止后的异步清理可能再次暂停，覆盖刚点击的继续。现在按用户操作版本识别过期清理。
4. 排队续跑异步准备期间的暂停无法撤销准备。现在撤销准备并重新排队，暂停后快速继续会触发一次新调度。
5. 新对话先清除当前会话 ID，编辑锁没有释放。现在保存编辑所属会话 ID 后解锁；收到取消/替代状态也退出失效编辑。
6. V2 启动恢复在空闲会话上可能直接发送已有队列项，绕过队列所有权。现在优先识别队列记录，保留队列调度入口。
7. 调度启动失败只标记队列失败，V2 仍可在重启时重发。现在同步终结尚未投递的 V2 接收记录。
8. 异常进程退出恢复为空闲后可能立即发送剩余队列。现在恢复先暂停，等待用户继续。
9. 取消队列项与删除 V2 原来分步执行，后一步失败会留下半完成状态。现在同事务提交；回滚用实际 SQLite 触发器故障验证。

附件 effect 的读回、完整性校验和同步分页也加入检查，避免正文保存成功但后续操作被 effect 哈希校验阻断。

## 场景矩阵

“自动化”指数据库、调度器、准备取消和共享状态规则的回归检查；“CDP”指运行中的真实 dev 和模型回复。不能把共享规则通过等同于所有供应商实际执行通过。
