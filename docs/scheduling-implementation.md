# 本地定时任务与定时消息

侧边栏的「定时任务」面板只管理独立任务，支持新建、编辑、暂停、启用、删除、立即执行和查看运行会话。定时消息从当前会话 Composer 的「+」菜单创建，默认一次性、1 小时后发送。主表单始终显示消息正文、发送方式和可编辑的延迟或指定时间，编辑已有消息时也直接显示时间输入框。无需展开高级设置即可切换「延迟发送」和「指定时间发送」。展开「高级设置」后配置可选名称、固定间隔、Cron、补跑窗口和预览。未填写名称时使用消息首行作为列表名称。

待发送的消息显示在该会话的 cards 中，可编辑、暂停、启用、删除及立即发送。会话搜索弹窗增加「定时消息」分区，按名称、正文或会话名称搜索，选中后打开对应会话并展开 cards。一次性消息成功交给普通会话消息队列后，自动从 cards 和搜索中移除，无需等待 Agent 完成该轮处理；聊天中保留实际消息。未投递的到期、暂停和失败消息仍可查看处理原因。周期消息保留其规则；一次性消息的「立即发送」会消耗原定日期，避免再次发送。内部执行回执和创建请求凭据继续保留，供恢复与去重使用。

延迟从保存时开始计算；相同内容的创建重试复用请求 ID 和已计算的日期，避免响应丢失导致重复创建。编辑正文保留原定日期，只有明确修改时间才重新计时。展开和收起高级设置都不改变时间模式或时间值，也不隐藏主表单的时间输入。固定间隔的首次发送可直接用延迟或指定时间设置；收起高级设置仍显示重复规则摘要。

## 两种执行方式

| 类型 | 上下文 | Core 与主模型 | 执行入口 |
| --- | --- | --- | --- |
| 定时消息 | 目标会话当时的历史 | 目标会话当时的配置 | 普通后续消息队列，等待当前轮结束 |
| 定时任务 | 每次创建新会话，指令必须包含必要背景 | 保存时固定的配置 | 普通会话创建与 Core 分发 |

定时消息向 Agent 投递原始正文。名称和来源作为独立的消息属性保存，聊天界面只显示「定时消息」标签，复制与编辑保留正文。此前已投递的消息保持历史记录，不追溯改写。

Agent 自主创建任务时，宿主读取当前会话的 Core 和有效主模型，包括会话中的模型覆盖和候选模型实际映射。保存后移除主模型的软引用，防止候选模型默认值变化悄悄改变执行模型。任务执行保留已保存的编排快照，不重新读取全局模板。用户在管理面板修改 Core、模型或运行配置；Agent 的内容更新保留用户已保存的执行配置。

定时会话使用现有权限、审批、会话模式和运行生命周期。本功能没有新增子代理调度规则。

## 时间和执行记录

- 支持一次性时间、从固定锚点开始的间隔、五字段 Cron。间隔至少 60 秒，Cron 明确保存 IANA 时区，不支持随机 `H` 字段。
- 时间以 UTC 落盘，面板按当前本地时区展示，并提供未来五次触发预览。Cron 使用 `cron-parser 5.10.1`：夏令时不存在的本地时间顺延，重复时间执行一次；已覆盖纽约 2026 年春秋转换测试。
- Eco 主进程运行时，每秒检查到期项目。存在启用且待触发的定时任务、定时消息，或待投递/投递中/运行中的定时执行记录时，阻止系统自动休眠；普通会话运行、后台终端任务和上下文压缩同样保持系统唤醒，屏幕仍可熄灭。暂停、删除、完成后在没有其他工作时释放，启动时恢复已有安排，系统唤醒后重新申请防休眠。应用退出、手动休眠或合盖仍可能中断执行；恢复后只合并到最近一次到期时点，默认允许迟到 24 小时，用户可设为 0–24 小时。
- 同时执行一个后台定时项目。忙碌的会话不被打断，已有队列暂停、计划、阻塞问题和审批也不会被越过。定时任务启动前检查同目录中的活跃会话。
- 修改尚未开始的执行会更新其配置；改变触发时间、暂停或删除会取消旧的待执行记录。已启动的记录保持原快照。
- 运行失败或无法确认是否已启动时暂停安排，显示原因。需要审批或用户处理时记录为「等待用户处理」，用户可打开对应会话继续。
- 时间规则与每次执行分别存入本地 SQLite。定时执行使用稳定的 occurrence、消息和会话 ID。创建及「立即执行」使用请求 ID 去重，删除后的创建重试不能复活安排。
- 重启检查已有会话和队列回执。已接受但没有可靠队列回执的消息保留为状态不确定；不会自动再次向 SDK 投递。

## Agent 工具

Claude、Codex、PI 和 Cursor ACP 通过当前会话认证的 MCP 使用以下工具。定时工具注册为 `eco_scheduling`，经现有 Eco MCP Hub 提供；ACP 复用现有的 MCP 配置转换和会话注入流程。

| 工具 | 用途 |
| --- | --- |
| `schedule_message` | 在当前会话安排一次自动唤醒 |
| `create_scheduled_task` | 保存独立、自包含的任务，自动继承当前 Core 与主模型 |
| `list_schedules` | 查看当前会话创建的安排，或当前运行所属任务 |
| `update_scheduled_task` | 修改任务名称、指令和时间，不能修改 Core、模型或工作目录 |
| `cancel_schedule` | 取消安排；已经开始的会话继续遵守现有停止机制 |

自动唤醒限制为 60 秒至 24 小时之间，每个会话每滚动 24 小时最多创建 24 次，同时只能存在一个未触发的自动唤醒。删除或改名不能重置计数。用户停止会话会暂停该会话的自动唤醒，并撤销当前运行的定时工具凭据。用户手动安排消息可使用周期规则。

Cursor ACP 在没有模型输出的启动失败时，保留定时投递的消息和原始指令，不将其退回用户输入框。失败原因和执行记录仍可查看。

第一版使用现有本地工作目录和普通会话机制，没有独立的云调度服务、定时任务专用 worktree 设置、费用预算或通知策略面板。研究设计中的这些建议并未作为本次已实现能力。

## 验证

入口调整及轻量表单通过会话搜索、Composer 菜单、工作区卡片、消息延迟、时间规则、配置快照、队列启动及执行状态检查共 34 项 Bun 测试。消息测试覆盖保存时起算、编辑正文保留原日期与毫秒、保留周期规则、固定间隔的延迟首次发送、无效延迟和自动名称。队列领取后启动 Core 的异步间隙保持运行中；重启后缺少活跃投递的领取回执保持结果不确定，不误判为成功。

新增时间、有效模型快照、SQLite 持久化、创建/运行去重、删除重试、迟到合并、自动唤醒预算、审批等待、并发、配置编辑、未知状态恢复和 MCP 会话权限测试。桌面 CDP 验证使用独立的 `SchedulingSmoke` 数据目录，不写入日常 Eco 数据。

防休眠回归通过 45 项相关测试，覆盖未来安排在启动时恢复、过期待投递、暂停/删除、一次性消息配置清理后继续运行、投递中删除配置、审批暂停、普通工作与定时工作并存、退出后迟到回调及唤醒重建断言。macOS 使用真实 Electron 37.10.3 和独立临时 SQLite，通过 `pmset -g assertions` 检查任务运行、等待定时触发、后台终端、上下文压缩时的系统防休眠断言，以及完成/暂停/退出后的释放；唤醒刷新还检查原生断言 ID 确实更换。本次未执行实际休眠、合盖或长时间无人值守测试。

前序实现通过 69 项 Bun 测试（含相关会话配置、队列、MCP 与 ACP 回归）。当前 SQLite/MCP 测试共 18 项，新增一次性消息消耗、立即发送不重发、投递失败保留原因、投递中修改未来日期、重启清理已投递配置而不重发的覆盖。桌面验证覆盖简单创建、正文编辑不改发送时间、Cron 预览与收起后保存、立即发送移除 cards 和搜索结果、原文和 TAG 保留，以及前序的任务模型编辑、暂停、定时投递和重启去重。本机 Cursor 未登录，真实 SDK 启动验证止于明确的认证失败；成功完成任务的调度路径通过模拟运行回执测试验证，未宣称已通过真实模型完成任务的端到端验证。
